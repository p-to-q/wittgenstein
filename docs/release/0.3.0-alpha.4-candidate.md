## Executable release path

Use the exact clean, qualified `main` commit. Do not publish today's code as
`0.3.0-alpha.3` or retarget an existing tag. The source version, CLI package,
packed executable, intended tag, build source commit and lockfile must agree:

```bash
pnpm install --frozen-lockfile
pnpm test:release
pnpm release:npm-cli
pnpm release:check --tag v0.3.0-alpha.4
```

The emitted JSON identifies the tarball and local `release.json` under
`artifacts/runs/release-*/`. `local-only` means no publication occurred. A dirty
local build remains inspectable but cannot pass the publication guard. After
editing or changing commits, rebuild; do not reuse a candidate from a different
source SHA. Build provenance is embedded in the public package metadata without
including data, training code, weights or credentials.

An authorized npm publisher then runs:

```bash
npm whoami
npm access list collaborators wittgenstein-cli --json
pnpm publish:npm-cli
pnpm release:check --tag v0.3.0-alpha.4 --require-npm
```

The helper publishes its checked `.tgz` with `--tag next` for this alpha and then
verifies the registry's exact version, SHA-512 integrity and `next` target. The
stable `latest` tag is deliberately preserved. The manual OTP variant is in
[distribution](../distribution.md). Following an uncertain publish response,
reconcile public metadata first; an existing conflicting version must be refused,
not overwritten or repeatedly published. Registry availability/authentication
failures do not establish whether publication occurred.

Only after public npm verification succeeds should the matching tag be created
on the same qualified source commit and pushed upstream. The Release workflow
rebuilds from the tag and checks public npm before publishing on GitHub. If
Actions remains unavailable, a maintainer can use the same verified artifacts
for a manual GitHub release, after checking the tag's resolved commit and
prerelease flag. A manually published draft bypasses workflow enforcement and
therefore requires that explicit positive registry check first. Do not treat a
successful Vercel deployment or skipped review as repository CI.

After publication, read back all of the following independently:

- `wittgenstein-cli@0.3.0-alpha.4` exists with the checked integrity and
  `next: 0.3.0-alpha.4`; `latest` remains the stable channel.
- The GitHub release is public, named/tagged `v0.3.0-alpha.4`, marked prerelease,
  and its immutable tag resolves to the exact qualified source commit.
- Install the public version in an isolated consumer directory and check
  `wittgenstein --version`, `doctor` and deterministic no-provider routes.
- Record source/lockfile hashes, tarball integrity, commands and actual outcomes.
  Public install readback is separate from an equivalent local-tarball test.

## Qualification and research scope

The snapshot repair is merged in
[PR #740](https://github.com/p-to-q/wittgenstein/pull/740). Its merged main
`07a2e9702e7b8ec68fc1f541966fe417696e367a` passed local frozen install, full
build/typecheck/lint/package tests, goldens, reviewer bench and **172 CPU training
checks with zero skips**. The overlapping dependency-light lane discovered 139
checks: 124 passed and 15 optional cases skipped. Local receipts are under
`artifacts/runs/20261127-resume-snapshot-binding/main-regression/`.

An isolated installation of the first candidate exposed a real packaging defect:
CommonJS output erased `import.meta.url`, so `--version` succeeded while `doctor`
crashed with `ERR_INVALID_ARG_VALUE`. The bundle now supplies its own file URL
for module-relative probes. Standalone regressions cover both missing and
resolvable optional ONNX peers; the release check and CI also execute the packed
`doctor`. The initial failed consumer receipt is retained rather than relabeled
as a successful installation.

A subsequent local-tarball consumer installed offline with optional dependencies
omitted, ran `--version` and `doctor`, matched all five reviewer-bench artifact
hashes, and passed both SVG and sensor replay round-trips. Replay baselines use
the same default-basename convention as the reviewer bench; initial probe/fixture
failures are retained separately. This proves the tested local package, not a
public npm install or optional decoder readiness. See
[the qualification report](../research/2026-11-27-release-alignment.md).

Release-specific regressions additionally cover metadata/binary/tag drift,
source/lockfile drift, dirty source, registry shape, absent versions,
artifact-integrity drift and channel drift. Final candidate qualification and
source hashes are recorded under `artifacts/runs/20261127-release-alignment/` and
in each generated release receipt. Those are local evidence, not an off-machine
backup or successful public installation.

No paid inference, GPU training, pretrained downloads, real-corpus sweep, weight
publication or image-quality claim belongs to this release check. #400/#402
corpus/rights and weight-identity gates, M1B training/acceptance, target-machine
qualification and #661's live CI/enforcement gate remain separate. Governance
PR #711 and research PR #720 still need independent review.
